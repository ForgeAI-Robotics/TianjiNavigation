# Hybrid A*可变点位导航开发 v6

在Jetson独立目录运行。输入来自只读雷达/里程计、保存地图和实测关节；没有底盘SDK、速度发布器、导航执行桥或生产导航目标写入。

启动：`bash ~/Desktop/导航.sh`。命令：

- `targets`：显示1号、2号可编辑目标。
- `set 1 X Y 朝向度` / `set 2 X Y 朝向度`：修改开发系统目标，版本递增，旧规划立即失效；原始保存点位不变。
- `localize`：在已有地图结构范围内全局重定位。
- `plan 1` / `plan 2`：重新定位、读取实测姿态、冻结场景并规划；此交互入口采用用户已确认的“双臂净空满足”假设。
- `status` / `quit`。

非交互：`./run.sh --goal 2 --assume-clearance`。
复现实验：追加 `--replay <某次结果/localization>`，明确使用旧快照，不冒充当前位置。

## 当前实现

1. 全局定位：双雷达各3帧，静态采集；不用历史当前位置或目标作初值。高度分层FFT相关搜索平移与72个朝向，12个候选经PCL GICP筛选，前后雷达独立时间留出验证，再对原始5cm地图精配准。检查次优解歧义、平面可观性、姿态合理性和外参/地图哈希。地图外或证据不足拒绝定位。
2. 目标：1/2从v5保存点初始化，各自可修改X/Y/朝向；带地图ID、版本和历史。目标变化要求重规划。
3. 全局路径：真正连续位姿Hybrid A*，不是Lattice。前进/倒车直线与曲线、原地旋转为主，包含方向反转、曲率、模式切换和朝向不连续惩罚。3D碰撞沿弧线采样；输出用更密采样独立复核。目标没有被自动挪动。
4. 横移策略：
   - 总距离≤1.5m、轴向偏移≤0.35m、朝向差≤10°的简单情形，可先试一条完整扫掠检查通过的短平移。
   - 其他情况先搜差速路线；只有该阶段失败才启用局部横移原语。
   - 长路线仅在机体附近有障碍或接近目标时允许横移，每个连续横移段≤0.4m，总横移预算≤min(1.5m,路线直线距离的25%)。
   - 横移里程代价为前进3倍，加启动/模式切换惩罚，不作为长距离全向导航。
5. 环境：静态地图＋最后一帧完整双雷达；地面分离；未知栅格不按空闲处理。底盘68×64×39cm代理及支撑结构、当前固定姿态的URDF体积参与碰撞检查。使用高度相关的搜索范围裁剪以控制计算量。
6. 反馈跟随器原型：`modules/follower.py`只返回速度建议，没有输出接口。差速段vy严格为0，只有规划的局部横移段允许vy；目标版本变更、定位过期、障碍/未知立即返回0。速度上限沿用X0.20、Y0.04、倒车0.10m/s、旋转0.20rad/s。仅完成数学仿真，未完成实车闭环验收。

## 净空假设与数据边界

`--assume-clearance`仅表示算法预览假设，不写回ShapeMask，不伪造相机实测，不产生运动许可。没有进行任何底盘运动试验。

原始点云、地图、URDF与相机/雷达外参保持不变。当前机体重叠点单独保存为`scene/current_body_ambiguous.npz`，不作为空闲证明。用户假设范围内的当前上部臂架近体不确定回波列为独立的预览歧义；底盘和下部支撑柱不享受该上部假设。原始保守拒绝结果保存在更早的试验目录中。

地图仍是人工清理后的可视化副本，未获导航验收；底盘/model坐标对齐、完整自由空间覆盖、动态障碍和物理制动尚未验证。实时执行必须另外接真实净空/新鲜定位与独立近场碰撞检查，不能直接接本目录输出驱动底盘。

“任意位置”限于有足够已建图结构、能唯一定位、起终点可行且有受支持通路的位置；不能保证地图外、盲区或不可达目标可导航。位置容差75mm/5°为当前原型判定，不是绝对定位精度承诺。

## 实测与验证

- 实景全图重定位通过，结果见各`results/.../localization/localization.json`，有独立双雷达匹配质量与候选歧义报告。
- 当前真实快照的下部支撑柱/底盘近场仍出现占据冲突，实景规划正确拒绝，不通过删除冲突或画替代路径宣称可行。若已经在目标位置容差内，只报告位置到达，运动继续禁止。
- `tests/test_navigation.py`验证可编辑目标、全局搜索、长距离差速绕障、短距离横移、狭窄起点局部横移脱困、已占据起点/未知区域拒绝，以及跟随器停止条件。
- `results/synthetic_examples/hybrid_policy_examples.png`明确为合成场景示例，线条来自C++搜索实际输出，非当前房间的可执行路线。

本目录`experiments/lattice_adapter`是先前未启用的Lattice适配草稿；活动入口仅调用`native/hybrid`。未修改v3/v4/v5原有导航/遥操/建图、S100生产导航或现有地图。


临时立柱线材忽略（2026-10-28）

用户确认整理后的立柱附近回波来自自身线材，当前仅在 v6 隔离导航预览启用。CLI `cables on/off/status` 控制开关；切换使旧路线失效，需重新规划。该规则不接入 S100 原导航。

限定原模型固定立柱/支架、底盘坐标高度 0.40–0.95 m、距支撑体表面 0.10 m 内且距柱中心水平不超过 0.23 m，只排除当前雷达的细小回波及竖直线束候选。连通的较宽平面、向区域外延展的物体、超预算或模型版本不一致的数据保留。该规则是基于用户确认区域的临时几何排除，不具备线材语义识别能力；该小区域内形似线材的外物仍可能被排除，不能将其作为自由空间证明或运动放行。

原始采集、被忽略点、规划点云分别保存，历史地图不删点，原 URDF、速度上限及碰撞间隔不变。`scene/temporary_pillar_cables.json` 记录每路滤除数量和几何依据；`temporary_pillar_cables.npz` 保留忽略点。点云档案 exports 中可分别查看原始/规划/忽略 PCD。异常点云窗口以橙色显示临时忽略点，红色显示剩余冲突，仍为保存快照。

验证：18 项测试通过，包含墙面、桌面、跨区域桌沿、手部体积保留和线束排除测试。`results/pillar_cable_review/verification.json` 保存同帧前后对照及后续新采集结果；当前仍有底盘附近冲突，执行接口始终关闭。


扩大自我滤除包络（2026-10-28 后续）

按用户要求，独立配置 `config/self_filter_envelope.json` 将 YD_link 底盘、固定立柱及支架的自我滤除包络设为表面外 6 cm；原始点采用 6 cm，体素另加半对角线（5 cm 体素合计约 10.33 cm）。只用于当前姿态下的自我/接触不确定区，不修改随路径移动的碰撞模型、原URDF、5 cm碰撞安全间隔、速度上限或原地图文件。当前姿态附近的历史占据体素也会从本次预览场景隔离，原地图和单独的排除点档案均保留。

CLI `self on/off/status` 控制本包络；改变后需重新规划。青色为扩大包络新增排除的点，橙色为之前的临时线材候选。包络内真实外物同样可能被排除，故仅用于隔离预览，自我排除不提供自由空间或执行许可。`scene/self_filter_envelope.{json,npz}` 保存配置、逐路数量及额外排除的原始点/体素。验证见 `results/self_envelope_review/verification.json`，同帧碰撞体逐项相同、速度策略相同，近身冲突 24→0，新帧 0；目标位置仍由原碰撞体拒绝。21项测试通过。

2026-10-29 导航配置GUI与短距离直角平移

桌面“导航配置”或 `bash ~/Desktop/导航GUI.sh` 打开目标1/2选择、地图标点、速度配置、重新定位/规划及路径图。点云查看器也提供“导航配置…”入口。按钮只调用本地规划预览，实机导航按钮明确禁用：自主执行接口、持续定位与独立实时碰撞守护尚未接为执行链，不能从本窗口发速度。关闭或取消只终止规划进程。

短距离规则：目标直线距离≤1.5m、两段轴向路程之和≤2m、目标朝向差≤10°，优先验证两个固定朝向的直角平移候选（先横移/先直行）。逐段以≤1.8cm间隔复检三维碰撞及二维已知候选区，方向不在转角处旋转；终点仅修正必要朝向。失败时回落原差速Hybrid A*及有限横移策略，长距离规则不变。配置 `short_rectilinear_enabled` 和 `short_rectilinear_max_length_m` 可调整，速度上限不变。25项回归测试通过，包括直角平移不转向及双段障碍拒绝。

对实际新环境2→1复算：差速路径约1.4m通过；固定朝向横移初段仍命中立柱附近点，另一顺序进入未知地面候选区，所以该帧没有强制选择平移。诊断见 `results/gui_navigation_20261029/check_translation.py`。二维候选区现包括本地图中实际走过的底盘脚印，但不清除任何三维障碍点；体积碰撞复检仍必须通过。此功能仅为规划候选补充，不是盲区自由空间认证。
